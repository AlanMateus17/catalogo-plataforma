Verificar se está tudo funcionando

Antes de publicar, confira tudo como um profissional: as ferramentas do navegador mostram o que está errado, e o Verificador confere o seu projeto inteiro de uma vez.

8.1 As ferramentas do navegador (F12)

Aperte F12 no Chrome ou no Edge. Estas são as abas que você vai usar:

AbaPara que serveComo usar
ElementosVer o HTML e o CSS de qualquer parte da páginaBotão direito num elemento, Inspecionar. Dá para mudar o CSS ao vivo e testar antes de mexer no arquivo.
ConsoleVer os erros e as mensagens do JavaScriptErro em vermelho: clique no nome do arquivo para ver a linha.
RedeVer se todos os arquivos foram encontradosCom a aba aberta, recarregue (F5). Arquivo em vermelho com 404 = caminho errado. Um 404 de favicon.ico pode ser ignorado: é o navegador procurando um ícone que o site não tem.
AplicativoVer o que o site guardou no navegadorArmazenamento local mostra, por exemplo, o tema escuro e as tarefas salvas.
LighthouseDar nota para acessibilidade, boas práticas e SEOClique em Analisar carregamento de página. Tente chegar a 90 ou mais.

Confira: a sua foto não aparece e o Console não mostra erro de JavaScript. Em qual aba você descobre o problema?

Ver a resposta

Na aba Rede: recarregue a página e procure a foto em vermelho com o código 404. O nome ou a pasta no src está diferente do arquivo real.

8.2 O Verificador do projeto

O Verificador lê a pasta do seu projeto e confere, de uma vez:

  • se o CSS, o JS e as imagens estão nos caminhos que o HTML diz, inclusive maiúsculas e minúsculas;
  • se o <head> tem o que precisa e se existe um único h1;
  • se toda imagem tem alt e se nenhum id se repete;
  • se o JavaScript procura algum id que não existe no HTML;
  • se sobrou <style> ou <script> dentro do CSS ou do JS, ou uma chave sem fechar.

Os arquivos não são enviados para lugar nenhum: a análise acontece no seu navegador.

Abrir o Verificador

8.3 Validador do W3C e Lighthouse

  1. Abra validator.w3.org e clique na aba Validate by Direct Input.
  2. Copie todo o seu index.html, cole e clique em Check.
  3. Corrija os itens marcados como Error, de cima para baixo. Um erro no começo costuma causar vários outros depois.
  4. Rode o Lighthouse. Em Acessibilidade, ele aponta, por exemplo, textos com pouco contraste e campos sem label.

Você tenta

Rode o Lighthouse no seu site, anote as notas, corrija um dos itens apontados em Acessibilidade e rode de novo. A nota subiu?

8.4 Guardar no GitHub

Terminou este passo? Registre a versão e envie. Assim, se o computador do laboratório for formatado, o seu trabalho estará salvo no GitHub.

Git Bash
$ git status$ git add .$ git commit -m "Corrige problemas apontados na verificação"$ git push

Troque a mensagem se quiser: ela deve dizer o que mudou. O site ainda não está no ar; publicar é o Passo 9.

Outro computador, ou começou a aula agora? Antes de editar, traga o que já está no GitHub: veja o Passo 10.3.
