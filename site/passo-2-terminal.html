2.1 Abrir o Git Bash e ler o prompt

Abra o Git Bash pelo menu Iniciar. A linha que aparece se chama prompt. Ela diz onde você está:

aluno@LAB-07 MINGW64 ~/projetos/turismo-barbacena (main)
$ ▌
  • aluno@LAB-07 quem você é e em qual computador
  • MINGW64 o tipo de terminal (pode ignorar)
  • ~/projetos/turismo-barbacena a pasta onde você está agora. O ~ é a sua pasta pessoal (C:\Users\aluno)
  • (main) só aparece dentro de um repositório Git
  • $ o terminal está esperando você digitar

Erro comum: digitar o $ junto com o comando.

O $ faz parte do prompt, não do comando. Nesta trilha ele aparece antes dos comandos só para mostrar que é algo para digitar no terminal. O botão Copiar já copia sem ele.

Erro comum: aparecer (main) na sua pasta pessoal (~).

Quer dizer que alguém rodou git init na pasta errada e ela inteira virou um repositório. É perigoso: um git add . ali tentaria guardar o seu computador inteiro. Veja como desfazer no Passo 4.2.

Três atalhos que poupam muito tempo:

  • Tab completa o nome de pastas e arquivos. Digite cd proj e aperte Tab.
  • ↑ traz de volta o último comando.
  • Ctrl + C sem nada selecionado cancela o comando que está rodando. Para copiar e colar: na janela do Git Bash, selecione com o mouse (já copia) e cole com Shift + Insert; no terminal do VS Code, selecione e use Ctrl + C e Ctrl + V.

Confira: você está em ~/projetos/turismo-barbacena e roda o comando cd .. — onde vai parar?

Ver a resposta

Em ~/projetos. O .. quer dizer "a pasta de cima".

2.3 Treino guiado (e a pasta dos seus projetos)

Todos os seus projetos vão morar numa pasta projetos, dentro da sua pasta pessoal. Não use Documentos nem Área de Trabalho: em muitos computadores elas são sincronizadas pelo OneDrive, o que atrapalha o Git.

Digite um comando por vez e compare a resposta com a esperada. Os comentários (linhas com #) não são copiados.

Git Bash
$ cd ~$ mkdir -p projetos$ cd projetos$ pwd$ mkdir treino-terminal$ cd treino-terminal$ touch teste.txt$ ls$ cd ..$ ls

O -p do mkdir evita erro se a pasta já existir.

O que o pwd, o primeiro ls e o segundo ls mostram (seu usuário no lugar de aluno)

/c/Users/aluno/projetos
teste.txt
treino-terminal/

Abra o Explorador de Arquivos, vá em C:\Users\ + o seu usuário e confira: a pasta projetos e a treino-terminal estão lá. O terminal e o Explorador mostram as mesmas pastas.

Erro comum: bash: cd: projetos: No such file or directory.

A pasta não existe onde você está. Rode pwd para ver onde está e ls para ver o que existe ali. Volte com cd ~ e repita.

Erro comum: nome de pasta com espaço.

cd Minha Pasta não funciona: o terminal acha que são duas coisas. Use aspas, cd "Minha Pasta", ou, melhor ainda, nunca use espaço em nome de pasta de projeto.

Você tenta

Dentro de treino-terminal, crie uma pasta fotos e, dentro dela, um arquivo lista.txt. Depois volte para treino-terminal e rode ls fotos. Deve aparecer lista.txt.

2.4 O terminal dentro do VS Code

O VS Code tem um terminal embutido que já abre na pasta do projeto. Isso evita o erro mais comum da trilha: rodar comandos na pasta errada.

  1. No VS Code, aperte Ctrl + Shift + P, digite Terminal: Select Default Profile e escolha Git Bash.
  2. Abra o terminal pelo menu Terminal > Novo Terminal (ou Ctrl + ', a tecla das aspas, à esquerda do 1).
  3. Confira no canto direito do terminal: deve estar escrito bash. Se estiver powershell, alguns comandos dos passos 4 e 9 não funcionam.

Confira: por que é mais seguro usar o terminal do VS Code do que abrir o Git Bash pelo menu Iniciar?

Ver a resposta

Porque o terminal do VS Code abre na pasta que está aberta no VS Code, que é a pasta do projeto. O Git Bash do menu Iniciar abre na sua pasta pessoal (~), e aí é fácil rodar um comando no lugar errado.

Pronto quando

Marque cada item só depois de conferir. As marcações ficam salvas neste navegador e aparecem na página inicial da trilha.
