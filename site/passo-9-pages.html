Publicar no GitHub Pages pelo terminal

O GitHub Pages transforma o repositório num site com endereço público. Um comando o ativa e, em poucos minutos, qualquer pessoa consegue abrir o seu site, até pelo celular.

9.1 Ativar o GitHub Pages pelo terminal

No terminal do VS Code (tem que mostrar bash, Passo 2.4), na pasta do projeto (confira com pwd), rode:

Git Bash
$ MSYS_NO_PATHCONV=1 gh api --method POST "repos/{owner}/{repo}/pages" -f "source[branch]=main" -f "source[path]=/"

Copie exatamente como está, com as chaves {owner} e {repo}. O gh troca esses dois pelo seu usuário e pelo nome do repositório, lendo o repositório da pasta onde você está.

O que deve aparecer (um trecho)

{
  "url": "https://api.github.com/repos/seu-usuario/turismo-barbacena/pages",
  "status": null,
  "html_url": "https://seu-usuario.github.io/turismo-barbacena/",
  "source": {
    "branch": "main",
    "path": "/"
  },
  ...
}
Parte do comandoO que quer dizer
MSYS_NO_PATHCONV=1Avisa o Git Bash para não mexer no / do final. Sem isso, ele troca / por C:/Program Files/Git/ e o comando falha.
gh api --method POSTFaz um pedido direto ao GitHub, do tipo "criar"
"repos/{owner}/{repo}/pages"O que criar: o Pages deste repositório
source[branch]=mainPublicar o que está no ramo main
source[path]=/A partir da raiz do repositório, onde está o index.html

Confira: por que o index.html precisa estar na raiz do repositório?

Ver a resposta

Porque o Pages publica a partir da raiz (/) e o navegador abre o index.html primeiro. Se ele estiver dentro de outra pasta, o endereço do site mostra erro 404.

9.2 Conferir o endereço e esperar a publicação

Git Bash
$ gh api "repos/{owner}/{repo}/pages" --jq ".html_url"$ gh api "repos/{owner}/{repo}/pages/builds/latest" --jq ".status"

O que deve aparecer

https://seu-usuario.github.io/turismo-barbacena/
building

O segundo comando mostra a situação da publicação: building quer dizer que ainda está publicando. Espere um ou dois minutos e rode de novo (seta ↑). Quando aparecer built, abra o endereço no navegador. Se esse comando responder 404 logo depois de ativar, a primeira publicação ainda não começou: espere um minuto e rode de novo.

Abra também no celular, fora do Wi-Fi da escola: se abrir, o site está mesmo na internet.

Erro comum: HTTP 409 ao ativar.

O Pages já estava ativo neste repositório. Não precisa fazer nada: rode o primeiro comando do 9.2 para ver o endereço.

Erro comum: HTTP 404: Not Found ao ativar.

O gh não achou o repositório. Confira se você está na pasta do projeto (pwd), se o git remote -v mostra o endereço do GitHub e se o gh auth status mostra a sua conta.

Erro comum: HTTP 422 ao ativar.

Três causas possíveis: faltou o MSYS_NO_PATHCONV=1 no começo (copie o comando de novo pelo botão); o repositório está como privado (numa conta gratuita, o Pages exige público); ou o ramo main não chegou ao GitHub (faça o git push do Passo 4).

Erro comum: The term 'MSYS_NO_PATHCONV=1' is not recognized.

O terminal é o PowerShell, não o Git Bash. Troque para Git Bash (Passo 2.4) e rode de novo.

Erro comum: o endereço abre com 404 There isn't a GitHub Pages site here.

Espere mais uns minutos. Se continuar, confira se o arquivo se chama exatamente index.html (minúsculo) e se está na raiz do repositório.

Sem o GitHub CLI: ativar pelo site
  1. No repositório, clique em Settings, depois em Pages no menu da esquerda.
  2. Em Source, escolha Deploy from a branch.
  3. Em Branch, escolha main e / (root), e clique em Save.
  4. Espere de 1 a 3 minutos e recarregue: aparece Your site is live at com o endereço.

9.3 Como o link aparece no WhatsApp

Quando alguém compartilha o endereço do seu site, o WhatsApp mostra um cartãozinho com título, descrição e imagem. Quem decide o que aparece são linhas no <head>. O painel abaixo tem essas linhas, mais o ícone da aba:

  • Cole dentro do <head>, logo depois do <title>. O description já existe na estrutura: não repita a linha, só troque o texto.
  • A imagem do og:image precisa do endereço completo do site publicado: https://seu-usuario.github.io/turismo-barbacena/img/capa.jpg. Com caminho curto (img/capa.jpg), o WhatsApp não mostra a imagem.
  • Sem os arquivos favicon.png e capa.jpg na pasta img, apague essas duas linhas: elas dariam 404.
  • As linhas da fonte você já colocou no Passo 6. Não repita.
Git Bash
$ git add .$ git commit -m "Adiciona informações para compartilhar o link"$ git push

Você tenta

Espere a publicação (9.2), mande o endereço do seu site para o seu próprio WhatsApp e veja o cartãozinho. O WhatsApp guarda a primeira versão do cartão por um tempo: se você mudar depois, teste com um contato diferente.

9.4 Depois da trilha: o seu endereço principal

Um repositório com o nome exatamente igual a seu-usuario.github.io vira o endereço principal, sem nada depois da barra: https://seu-usuario.github.io/. É o lugar ideal para um portfólio com links para todos os seus projetos.

Isso é um projeto novo, numa pasta nova: repita os passos 3 e 4 com o nome seu-usuario.github.io (o seu usuário no lugar de seu-usuario). No gh repo create do Passo 4.4, use esse nome. O Pages desse repositório costuma ativar sozinho; se o site não aparecer em alguns minutos, rode o comando do 9.1 nele.

Pronto quando

Marque cada item só depois de conferir. As marcações ficam salvas neste navegador e aparecem na página inicial da trilha.
