3.1 Escolher o nome do projeto

O nome da pasta vira o nome do repositório e o final do endereço do site: https://seu-usuario.github.io/turismo-barbacena/. Nesta trilha, o exemplo é sempre turismo-barbacena: onde aparecer, use o nome do seu projeto.

  • Tudo em minúsculas, sem espaço (use hífen) e sem acento.
  • Curto e sobre o tema: receitas-da-vo, portfolio-ana, time-de-volei.

3.2 Criar a pasta e os arquivos pelo terminal

No Git Bash, troque turismo-barbacena pelo nome que você escolheu, nos dois comandos em que ele aparece:

Git Bash
$ cd ~/projetos$ mkdir turismo-barbacena$ cd turismo-barbacena$ mkdir css js img$ touch index.html css/estilo.css js/script.js$ ls -R

O que deve aparecer

.:
css/  img/  index.html  js/

./css:
estilo.css

./img:

./js:
script.js

O ls -R lista a pasta e tudo o que está dentro das subpastas. É a estrutura que o seu site precisa.

Confira: o que faz touch css/estilo.css?

Ver a resposta

Cria um arquivo vazio chamado estilo.css dentro da pasta css. A pasta precisa existir antes; por isso o mkdir veio primeiro.

3.3 Trazer as suas fotos (no tamanho certo)

Foto de celular pesa de 3 a 8 MB: deixa o site lento e o repositório enorme. Antes de copiar, diminua cada foto em squoosh.app (grátis, no navegador): largura de 1600 px no máximo, formato JPG ou WebP, qualidade perto de 75. Cada foto deve ficar abaixo de 300 KB.

Depois copie para a pasta img. Pelo terminal, já dá para acertar o nome:

Git Bash
$ cp ~/Downloads/IMG_2031.jpg img/praca-central.jpg$ ls img

cp origem destino: copia a foto de Downloads e, na mesma hora, dá a ela um nome em minúsculas e sem espaço.

Erro comum: foto com nome Foto 1.JPG.

Espaço atrapalha no terminal e nos endereços. Maiúsculas enganam: o Windows acha Foto.JPG quando o HTML pede foto.jpg, mas o GitHub Pages não acha, e a imagem quebra só no site publicado. Use sempre minúsculas e renomeie: mv "img/Foto 1.JPG" img/foto-1.jpg. Se o arquivo já foi enviado ao GitHub (Passo 4), renomeie com git mv no lugar de mv, senão o Git do Windows não percebe a troca de maiúscula.

3.4 Abrir no VS Code e colar a estrutura

Git Bash
$ code .

O VS Code abre com a pasta do projeto. Agora cole os três arquivos da estrutura inicial: abra o painel abaixo, copie cada aba e cole no arquivo indicado.

Abra o Entenda este código de cada aba: ele explica cada tag, propriedade e comando da estrutura.

Erro comum: bash: code: command not found.

O VS Code foi instalado sem a opção Adicionar ao PATH. Abra o VS Code pelo menu Iniciar e use Arquivo > Abrir Pasta. Na próxima reinstalação, marque a opção.

3.5 Ver o site no navegador e testar a conexão

  1. No VS Code, clique com o botão direito no index.html e escolha Open with Live Server (ou clique em Go Live, embaixo, à direita).
  2. O navegador abre em http://127.0.0.1:5500/index.html. Esse endereço só existe no seu computador: ninguém mais consegue abri-lo.
  3. Teste de conexão do CSS: no fim do estilo.css, escreva body { background-color: yellow; } e salve. A página fica amarela sozinha.
  4. Teste de conexão do JS: aperte F12 no navegador e abra a aba Console. Deve aparecer a mensagem script.js conectado!. Ela vem da linha que está no script.js da estrutura.
  5. Deu certo? Apague a linha do fundo amarelo.

Erro comum: o Live Server abre uma lista de arquivos em vez do site.

Ele não achou o index.html na pasta aberta. Confira se o arquivo se chama exatamente index.html e se você abriu a pasta do projeto (e não a pasta de cima).

Erro comum: a página não ficou amarela.

O caminho do CSS está errado ou o arquivo não foi salvo. Confira o <link rel="stylesheet" href="css/estilo.css"> letra por letra e aperte Ctrl + S. No F12, a aba Rede mostra o arquivo em vermelho com o código 404 quando o caminho não existe.

Você tenta

Troque o texto do <h1> pelo nome do seu site e salve. Não recarregue o navegador: o Live Server faz isso sozinho.

Pronto quando

Marque cada item só depois de conferir. As marcações ficam salvas neste navegador e aparecem na página inicial da trilha.
