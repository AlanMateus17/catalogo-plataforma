1. O que é HTML (e o que ele não é)

HTML quer dizer HyperText Markup Language: linguagem de marcação de hipertexto. Marcação é isto: você pega um texto e marca cada pedaço dizendo o que ele é. "Isto é um título." "Isto é um parágrafo." "Isto é um link que leva para outra página."

HTML não é linguagem de programação: ele não faz contas, não toma decisões e não repete nada. Ele só descreve o conteúdo. Cada linguagem do site tem uma função:

LinguagemPergunta que respondeArquivoComparação
HTMLO que é cada coisa da página?index.htmlO esqueleto e os órgãos
CSSComo cada coisa aparece?css/estilo.cssA roupa e a aparência
JavaScriptO que acontece quando a pessoa age?js/script.jsOs músculos: o movimento

Quando você abre um arquivo .html, o navegador lê o texto de cima para baixo, entende as marcações e monta uma árvore de elementos (o DOM). É essa árvore que o CSS pinta e que o JavaScript mexe. Por isso a organização do HTML importa tanto: uma árvore bagunçada deixa o CSS e o JS difíceis.

2. Anatomia de um elemento

Quase todo elemento tem três partes: a tag de abertura, o conteúdo e a tag de fechamento. A tag de fechamento é igual à de abertura, com uma barra /.

<a href="sobre.html">Saiba mais</a>
  • Tag de abertura: <a ...>. Diz onde o elemento começa e qual é o tipo dele (a = link).
  • Atributo: href. Uma informação extra sobre o elemento. Sempre dentro da tag de abertura.
  • Valor do atributo: "sobre.html". Entre aspas, depois do sinal de igual, sem espaço em volta do =.
  • Conteúdo: o que aparece na tela (pode ter outros elementos dentro).
  • Tag de fechamento: </a>. Diz onde o elemento termina.

Elementos vazios

Alguns elementos não têm conteúdo, então não têm fechamento: <img>, <br>, <hr>, <input>, <meta>, <link>. Tudo o que eles precisam vai nos atributos.

Atributos booleanos (liga/desliga)

Alguns atributos não precisam de valor: só de estarem escritos, já estão ligados. required, disabled, checked, hidden, defer, controls. Para desligar, apague o atributo (escrever required="false" NÃO desliga).

Aninhamento: uma caixa dentro da outra

Elementos podem ficar dentro de outros. A regra é a da caixa: o que abriu por último fecha primeiro. Quem está dentro é o filho; quem está fora, o pai.

Erro comum: tags fechadas na ordem errada

<p><strong>Atenção</p></strong> está errado: o <strong> abriu dentro do <p>, então tem que fechar antes dele. O navegador conserta sozinho, seguindo uma regra fixa, mas quase nunca do jeito que você queria: um elemento vai parar dentro de outro, e o CSS deixa de funcionar como o esperado.

Regras de escrita

  • Tags e atributos em minúsculas: <section>, não <SECTION> (funciona, mas não é o padrão).
  • Valores de atributo sempre entre aspas duplas: class="card destaque".
  • Espaços e Enter a mais no texto viram um espaço só na tela. Para espaço de verdade, use CSS (margin, padding).
  • Recuo (indentação) de 2 espaços para cada nível de dentro. O navegador ignora, mas é o que deixa o código legível.
  • Comentário: <!-- texto -->. O navegador ignora; serve para explicar.
  • Para escrever <, > e & como texto, use entidades: &lt; &gt; &amp;.

Experimente: veja a árvore que o navegador monta

Escreva ou cole HTML. A árvore mostra quem é pai e quem é filho. Tente fechar uma tag na ordem errada e veja o aviso.

Confira: No código <p>Olá, <em>mundo</p></em>, o que está errado?

Ver a resposta

O <em> abriu dentro do <p>, então precisa fechar antes: <p>Olá, <em>mundo</em></p>.

Os caminhos em href e src partem da pasta onde está o arquivo HTML. css/estilo.css = "entre na pasta css e pegue estilo.css". ../ = "volte uma pasta". Letras maiúsculas contam: no GitHub Pages, Foto.jpg e foto.jpg são arquivos diferentes.

4. Semântica: escolher a tag pelo significado

Semântica é o significado. Uma tag semântica diz o que o conteúdo é, e não como ele parece. Um <h2> e um <div class="grande"> podem ficar idênticos na tela, mas só o primeiro diz "isto é um título".

Por que isso importa se na tela fica igual?

  • Acessibilidade: pessoas cegas usam leitores de tela, que navegam pulando de título em título, de região em região (menu, conteúdo principal, rodapé). Com div para tudo, a página vira um bloco de texto sem mapa.
  • Google: o buscador entende o assunto pelos títulos e pelas regiões.
  • Manutenção: você (e o seu colega) acha as partes do código muito mais rápido.
  • Comportamento pronto: <button> já funciona com teclado, <details> já abre e fecha, <a href> já é clicável com Tab. Com div você teria que programar tudo isso em JavaScript.

Títulos em ordem, como um sumário

Os títulos formam o sumário da página: h1 é o título do livro, h2 os capítulos, h3 as partes de um capítulo. Nunca pule níveis (h2 direto para h4) e nunca escolha o título pelo tamanho: tamanho é trabalho do CSS.

Erro comum: usar h1, h2, h3 pelo tamanho da letra

Precisa de um texto grande que não é título? Use um p com uma classe e aumente no CSS. Precisa de um título pequeno? Use o nível certo e diminua no CSS.

Bloco e em linha

Por padrão, alguns elementos ocupam a linha inteira (bloco: <p>, <h1>, <section>, <div>, <ul>) e outros ficam no meio do texto (em linha: <a>, <strong>, <span>, <img>, <code>). Os elementos de texto, como <span>, <strong> e <em>, só aceitam texto e outros elementos de texto dentro: não coloque um <div> dentro de um <span>. O <a> é exceção: ele pode envolver um bloco inteiro, como um card. A aparência (bloco ou em linha) o CSS muda com display.

Confira: Um botão "Curtir" que muda um contador na página: <a> ou <button>?

Ver a resposta

<button>: ele faz uma ação na página, não leva para outro endereço. Link é para ir a algum lugar.

Você tenta

Pegue o seu index.html e procure todos os <div>. Para cada um, pergunte: existe uma tag com significado para isto? Troque os que tiverem.

5. Textos, links, imagens e mídia

Links

O texto do link deve dizer para onde ele leva. "Clique aqui" não diz nada para quem usa leitor de tela, que ouve a lista de links fora do contexto.

Imagens

AtributoPor que é obrigatório (ou quase)
srcSem ele não há imagem.
altDescreve a imagem para quem não enxerga e aparece se ela não carregar. Imagem só decorativa: alt vazio.
width e heightO navegador reserva o espaço antes de a foto chegar, e a página não "pula".

6. Formulários: conversar com o usuário

Formulário é como o site recebe dados: um contato, um cadastro, uma busca. Três regras resolvem 90% dos problemas:

  1. Todo campo tem um <label>, ligado pelo for = id do campo. Clicar no rótulo foca o campo, e o leitor de tela lê o nome.
  2. Todo campo tem name. É o nome do dado que vai ser enviado (e o que o FormData do JavaScript lê). Sem name, o campo é ignorado.
  3. Use o type certo: email, tel, number, date. O celular mostra o teclado certo e o navegador já valida.

Validação pronta

required, minlength, type="email" e pattern fazem o navegador conferir os dados antes de enviar, sem nenhuma linha de JavaScript. Mas quem manda no dado é o servidor: no módulo 12 (segurança) você vai ver por que o servidor precisa conferir tudo de novo (qualquer pessoa pode desligar a validação do navegador).

Para onde o formulário vai? O action é o endereço de um servidor que recebe os dados. Enquanto você não tem um, o JavaScript pode tratar o envio (evento submit com preventDefault). No módulo 9 (API), você vai criar o servidor que recebe esses dados.

7. Acessibilidade: um site para todo mundo

Acessibilidade é fazer o site funcionar para quem enxerga pouco ou nada, quem não usa mouse, quem é daltônico, quem tem pouca coordenação motora. No Brasil, a Lei Brasileira de Inclusão (art. 63) exige acessibilidade nos sites de empresas e de órgãos de governo. A boa notícia: HTML semântico já resolve a maior parte.

FaçaPor quê
alt em toda imagemÉ o que o leitor de tela lê.
label em todo campoSem ele, o campo é "editar texto" sem nome.
button para ações, a para linksJá funcionam com Tab, Enter e Espaço.
títulos em ordem (h1 → h2 → h3)É o mapa da página para quem não enxerga.
não tirar o contorno de focoQuem usa teclado precisa ver onde está. Troque o estilo, não apague.
contraste de cor suficienteTexto cinza-claro em fundo branco some para muita gente (e no sol, para todo mundo).
aria-label em botão só com íconeUm botão "✕" precisa de um nome: aria-label="Fechar".

Regra de ouro

A primeira regra do ARIA é não usar ARIA quando existe uma tag que já faz aquilo. Um <button> é melhor que <div role="button" tabindex="0">. Use aria-* para o que o HTML não tem: dizer se um menu está aberto (aria-expanded), dar nome a ícones (aria-label), avisar mudanças (aria-live).

Você tenta

Abra o seu site, coloque o mouse de lado e navegue só com Tab, Shift + Tab, Enter e Espaço. Dá para usar tudo? Você sempre vê onde está o foco?

Ferramentas para conferir:

  • Validador oficial: validator.w3.org/#validate_by_input. Cole o HTML e ele lista os erros com a linha.
  • F12 → Elements (Elementos): mostra a árvore que o navegador montou. O navegador acrescenta algumas tags sozinho (como <tbody> nas tabelas); mas se um elemento aparecer dentro de outro onde você não colocou, você errou uma tag.
  • Verificador do projeto deste site: verificador.html confere caminhos, alt, ids repetidos e tags sem fechar.

9. Como ler a documentação oficial (MDN)

Esta página é um começo. A documentação oficial usada por programadores do mundo todo é o MDN Web Docs (developer.mozilla.org), que tem versão em português. Aprender a ler documentação é uma das habilidades mais importantes da profissão: toda ferramenta nova que você usar vai ter uma.

  1. Pesquise no Google: mdn + o nome da tag ("mdn figure"). O primeiro resultado costuma ser a página certa.
  2. Leia o primeiro parágrafo: é o "o que é".
  3. Pule para Exemplos: copie, rode, mude uma coisa de cada vez.
  4. Olhe a tabela de Atributos: quais existem e o que cada um aceita.
  5. No fim, Compatibilidade com navegadores: verde = funciona.
