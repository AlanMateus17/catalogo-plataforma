Passo 4 de 10. Tempo: 1 aula

Guardar o projeto no GitHub

Antes de montar o conteúdo, o projeto ganha histórico e uma cópia no GitHub. Assim, do primeiro dia em diante, o seu trabalho nunca fica preso a um computador. São poucos comandos, mas todos precisam ser rodados dentro da pasta do projeto.

4.1 A ideia do Git em uma figura

Pasta do projetoos arquivos que você edita
git add
Preparadoso que vai entrar na próxima versão
git commit
Históricoas versões salvas, no seu computador
git push
GitHuba cópia na internet
Pages (Passo 9)
Site no arseu-usuario.github.io

Um commit é uma foto do projeto num momento, com uma mensagem dizendo o que mudou. Se algo quebrar amanhã, dá para buscar um arquivo na foto de hoje (Passo 10.2 ensina).

4.2 Estar na pasta certa (antes de tudo)

Abra o terminal do VS Code com a pasta do projeto aberta (Passo 2.4) e confira:

Git Bash
$ pwd$ ls

O que deve aparecer

/c/Users/aluno/projetos/turismo-barbacena
css/  img/  index.html  js/

O pwd precisa terminar com o nome do seu projeto, e o ls precisa mostrar só os arquivos do site. Se aparecer outra coisa, pare aqui.

Erro comum (e perigoso): rodar git init fora da pasta do projeto.

Os sinais: o prompt mostra (main) na sua pasta pessoal; o git add . demora muito e mostra avisos sobre AppData; o git status lista Desktop/, AppData/, Downloads/. Aperte Ctrl + C se algo estiver rodando e não faça commit nem push: você estaria guardando o seu computador inteiro, com senhas, num repositório público.

Para desfazer, faça um comando de cada vez, lendo a resposta antes de seguir. Primeiro, descubra onde está o repositório errado:

Git Bash
$ git rev-parse --show-toplevel

Exemplo de resposta

C:/Users/aluno

Vá até a pasta que apareceu (entre aspas, do jeito que ela foi mostrada) e confira que ela não tem nenhum commit:

Git Bash
$ cd "C:/Users/aluno"$ git log

A resposta tem que ser esta

fatal: your current branch 'main' does not have any commits yet

Só se a resposta foi does not have any commits yet, apague a pasta oculta .git. Se o git log mostrar commits, não apague: chame o professor.

Git Bash
$ rm -rf .git

O (main) some do prompt e nenhum arquivo seu é apagado.

4.3 Criar o repositório e fazer o primeiro commit

Git Bash
$ git init$ git status

O que deve aparecer

Initialized empty Git repository in C:/Users/aluno/projetos/turismo-barbacena/.git/
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        css/
        img/
        index.html
        js/

nothing added to commit but untracked files present (use "git add" to track)

O prompt agora mostra (main): a pasta virou um repositório. Os arquivos em vermelho ainda não fazem parte de nenhuma versão.

No laboratório (computador compartilhado): agora, logo depois do git init, diga ao Git quem você é, só para este projeto (sem --global):
Git Bash
$ git config user.name "Seu Nome Completo"$ git config user.email "seu-email@exemplo.com"

Só no laboratório. No seu computador, o Passo 1.6 já resolveu.

Git Bash
$ git add .$ git status

O que deve aparecer (agora em verde; os nomes das suas fotos mudam)

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
        new file:   css/estilo.css
        new file:   img/praca-central.jpg
        new file:   index.html
        new file:   js/script.js

O git add . preparou tudo (o ponto quer dizer "esta pasta inteira"). Agora salve a versão:

Git Bash
$ git commit -m "Primeira versão do site"$ git log --oneline

O que deve aparecer (o código de letras e números e as quantidades mudam)

[main (root-commit) 3f2a9c1] Primeira versão do site
 4 files changed, 128 insertions(+)
3f2a9c1 (HEAD -> main) Primeira versão do site

Avisos LF will be replaced by CRLF são normais no Windows e podem ser ignorados.

Erro comum: Author identity unknown no commit.

O Git não sabe o seu nome e e-mail. Rode os dois git config acima (no laboratório) ou os do Passo 1.6 e faça o commit de novo.

Erro comum: a pasta img sumiu do git status.

O Git não guarda pastas vazias. Coloque pelo menos uma foto em img e ela aparece.

Confira: qual é a diferença entre git add e git commit?

Ver a resposta

O git add escolhe o que vai entrar na próxima versão. O git commit salva essa versão no histórico, com uma mensagem.

4.4 Criar o repositório no GitHub e enviar com um comando

Troque turismo-barbacena pelo nome do seu projeto (o mesmo da pasta):

Git Bash
$ gh repo create turismo-barbacena --public --source=. --remote=origin --push

O que deve aparecer (um trecho)

✓ Created repository seu-usuario/turismo-barbacena on GitHub
  https://github.com/seu-usuario/turismo-barbacena
✓ Added remote https://github.com/seu-usuario/turismo-barbacena.git
...
✓ Pushed commits to https://github.com/seu-usuario/turismo-barbacena.git
Parte do comandoO que quer dizer
gh repo create turismo-barbacenaCria no GitHub um repositório com esse nome
--publicPúblico: qualquer um vê. O GitHub Pages gratuito exige isso.
--source=.Usa esta pasta (.) como origem
--remote=originChama o endereço do GitHub de origin, o nome padrão
--pushJá envia os commits

Abra o repositório no navegador para conferir:

Git Bash
$ gh repo view --web

Pronto: o projeto está guardado. Daqui em diante, todo passo termina com "Guardar no GitHub": git add, git commit e git push. O site só vai ao ar no Passo 9, depois de conferido.

Erro comum: Name already exists on this account.

Você já tem um repositório com esse nome. Escolha outro nome no comando, ou apague o antigo pelo site do GitHub (Settings > Danger Zone) se ele não servir mais.

Erro comum: error: src refspec main does not match any.

Não existe nenhum commit para enviar. Volte ao 4.3 e confira o git log --oneline.

Erro comum: fatal: not a git repository.

Você está fora da pasta do projeto. Rode pwd, vá para a pasta certa com cd ~/projetos/turismo-barbacena e repita.

Sem o GitHub CLI: criar pelo site e enviar pelo Git
  1. No GitHub, clique em + > New repository, dê o nome do projeto, marque Public e não marque "Add a README". Clique em Create repository.
  2. No terminal, na pasta do projeto:
Git Bash
$ git remote add origin https://github.com/seu-usuario/turismo-barbacena.git$ git push -u origin main

No primeiro push, o navegador abre pedindo login (no laboratório, lembre-se do aviso do Passo 1.7 sobre o Gerenciador de Credenciais). Se aparecer remote origin already exists, troque o endereço com git remote set-url origin e o endereço certo.

Pronto quando

Marque cada item só depois de conferir. As marcações ficam salvas neste navegador e aparecem na página inicial da trilha.
