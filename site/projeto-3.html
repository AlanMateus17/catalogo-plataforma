2. Antes de começar

O que você vai praticar: montar a página pelo JavaScript a partir de dados, filtros combinados, janela acessível, validação de formulário e lembrar escolhas do visitante.

O que estudar antes (ou durante)

Tudo o que este projeto usa está explicado na Documentação:

  • Listas e objetos
  • Criar elementos na página
  • Eventos
  • Guardar dados no navegador
  • Formulários
  • Acessibilidade

3. O que o sistema precisa fazer

Requisitos

  1. RF01 — Seções: apresentação, projetos, habilidades, contato.
  2. RF02 — Os cards de projeto são montados pelo JavaScript a partir de uma lista de objetos (nome, descrição, tecnologias, imagem, link do site, link do repositório).
  3. RF03 — Filtro por tecnologia: clicar em "CSS" mostra só os projetos que usam CSS; dá para combinar dois filtros.
  4. RF04 — Clicar num card abre uma janela com os detalhes do projeto.
  5. RF05 — Formulário de contato com validação (nome, e-mail, mensagem de 20 a 500 caracteres) e mensagem de confirmação.
  6. RF06 — Tema claro e escuro, lembrado na próxima visita.

Regras de negócio

  • RN01 — Acrescentar um projeto novo = acrescentar um objeto na lista. Nenhum HTML muda.
  • RN02 — Com dois filtros ligados, aparecem os projetos que têm as duas tecnologias.
  • RN03 — A janela fecha com Esc, com o botão fechar e clicando fora dela; ao fechar, o foco volta ao card.
  • RN04 — Nenhum filtro ligado = todos os projetos. Nenhum resultado = mensagem "Nenhum projeto com essas tecnologias".

4. Construa em 4 marcos

Não tente fazer tudo de uma vez. Termine um marco, confira que funciona, faça um commit e só então passe para o próximo.

Marco 1: A página estática

Funciona quando: as quatro seções existem, o menu leva a cada uma e dois cards de projeto estão escritos à mão no HTML.

Travou? Abra uma dica de cada vez, e só depois de tentar de verdade.

Dica 1: uma pergunta para pensar

O recrutador abre o seu site. O que ele precisa ver sem rolar a página?

Dica 2: o conceito que resolve

Seu nome e o que você faz no h1, um botão para os projetos e outro para o contato. Os dois cards escritos à mão são o molde que o JavaScript vai repetir no próximo marco.

Dica 3: onde estudar isso
  • Semântica
  • Flexbox
  • Grid

Marco 2: Os cards gerados pela lista

Funciona quando: você apaga os cards escritos à mão e eles aparecem do mesmo jeito, montados a partir de uma lista no JavaScript.

Travou? Abra uma dica de cada vez, e só depois de tentar de verdade.

Dica 1: uma pergunta para pensar

Compare os dois cards que você escreveu à mão. Quais partes mudam de um projeto para outro? Essas partes são os seus dados.

Dica 2: o conceito que resolve

Um array de objetos com essas partes e uma função que recebe um projeto e devolve o elemento do card, criado com createElement e preenchido com textContent. Um laço chama a função para cada projeto e coloca o card na página.

Dica 3: onde estudar isso
  • Listas e objetos
  • createElement, textContent e append
  • Funções

Marco 3: Filtros e janela de detalhes

Funciona quando: os casos 2, 3 e 4 funcionam.

Travou? Abra uma dica de cada vez, e só depois de tentar de verdade.

Dica 1: uma pergunta para pensar

Com "CSS" e "JavaScript" ligados, deve aparecer o projeto que tem qualquer um dos dois, ou só o que tem os dois? Qual método de lista pergunta "todos cumprem?"

Dica 2: o conceito que resolve

Guarde os filtros ligados num array e mostre o projeto se todo filtro ligado estiver nas tecnologias dele (every + includes). Para a janela, a tag <dialog> com showModal() já fecha com Esc; guarde qual card abriu para devolver o foco a ele.

Dica 3: onde estudar isso
  • Métodos de lista: every, some, includes, filter
  • Eventos
  • Foco e teclado

Marco 4: Formulário, tema e publicação

Funciona quando: os casos 5 e 6 funcionam e o site está no ar no endereço principal.

Travou? Abra uma dica de cada vez, e só depois de tentar de verdade.

Dica 1: uma pergunta para pensar

Onde o site guarda uma escolha do visitante para a próxima visita? E o que o HTML já valida sozinho, antes de qualquer JavaScript?

Dica 2: o conceito que resolve

localStorage guarda o tema. No formulário, required, type="email", minlength e maxlength já validam; o JavaScript chama checkValidity() e mostra a mensagem ao lado do campo. O endereço principal é um repositório chamado exatamente seu-usuario.github.io.

Dica 3: onde estudar isso
  • localStorage
  • Validação de formulários
  • Passo 9: GitHub Pages

5. Perguntas para pensar antes de programar

Responda no papel (ou no README). Elas apontam as armadilhas do projeto antes de você cair nelas. As respostas não estão aqui de propósito: é o que o projeto ensina.

  • Que forma de dado guarda "um projeto" com todas as informações dele? E "todos os projetos"?
  • Filtrar é esconder cards que já existem ou montar a lista de novo? Quais são as vantagens de cada jeito?
  • Qual elemento do HTML já é uma janela e já fecha com Esc?

Erro comum: o card mostra <strong> escrito, ou um texto do projeto quebra a página.

Use textContent para colocar dados na página, nunca innerHTML com texto vindo de uma lista: além de quebrar, é uma porta para código malicioso.

Erro comum: com um filtro ligado e depois desligado, não volta a mostrar tudo.

Confira o que a sua conta faz com a lista de filtros vazia. every numa lista vazia devolve true (todos aparecem); some devolve false (nenhum aparece).

Erro comum: o tema pisca claro antes de ficar escuro.

O tema é aplicado depois que a página já apareceu. Leia o localStorage e aplique o tema o mais cedo possível.

E a IA, neste passo?

Pode: pedir para explicar a diferença entre every e some, ou para revisar a acessibilidade da janela depois de pronta.

Não: pedir a função que monta os cards ou a do filtro. É com elas que você aprende a transformar dados em página.

Por quê, e prompts prontos para usar do jeito certo: Usar IA do jeito certo.
