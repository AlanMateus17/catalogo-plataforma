Quadro Kanban

Uma pequena equipe controla as tarefas num grupo de mensagens e perde o que foi combinado. Ela precisa de um quadro simples, que funcione no navegador, sem login, onde cada pessoa veja o que está parado, o que está andando e o que terminou.

2. Antes de começar

O que você vai praticar: estado da aplicação num array, redesenhar a tela a partir dele, arrastar e soltar com alternativa pelo teclado, ordenação, datas, e salvar, exportar e importar dados.

O que estudar antes (ou durante)

Tudo o que este projeto usa está explicado na Documentação:

  • Listas e objetos
  • Mudar a página
  • Eventos
  • localStorage e JSON
  • Tratar erros

3. O que o sistema precisa fazer

Requisitos

  1. RF1 — Três colunas fixas: A fazer, Fazendo e Feito.
  2. RF2 — Criar cartão com título (obrigatório), descrição, prioridade (baixa, média, alta) e data de entrega (opcional).
  3. RF3 — Editar e excluir cartão. Excluir pede confirmação.
  4. RF4 — Mover cartão entre colunas arrastando com o mouse e por botões ou teclado.
  5. RF5 — Cada coluna mostra quantos cartões tem.
  6. RF6 — Cartão com data de entrega vencida e fora de Feito aparece destacado.
  7. RF7 — Filtro por prioridade e busca por texto no título.
  8. RF8 — Tudo continua lá depois de fechar e abrir o navegador.
  9. RF9 — Exportar o quadro para um arquivo .json e importar de volta.

Regras de negócio

  • RN1 — A coluna Fazendo aceita no máximo 3 cartões. O 4º é recusado com um aviso, e o cartão volta para onde estava.
  • RN2 — Título vazio ou só com espaços não cria cartão.
  • RN3 — Cartão em Feito nunca aparece como atrasado.
  • RN4 — Dentro da coluna, a ordem é: prioridade alta primeiro, depois a data de entrega mais próxima.
  • RN5 — Importar um arquivo inválido não apaga o quadro atual; mostra o erro.

4. Construa em 4 marcos

Não tente fazer tudo de uma vez. Termine um marco, confira que funciona, faça um commit e só então passe para o próximo.

Marco 1: Colunas e cartões desenhados a partir dos dados

Funciona quando: as três colunas aparecem com cartões de exemplo que estão numa lista no JavaScript, e não escritos no HTML.

Travou? Abra uma dica de cada vez, e só depois de tentar de verdade.

Dica 1: uma pergunta para pensar

O quadro na tela e a lista no JavaScript: qual dos dois é a verdade? Se eles discordarem, qual vale?

Dica 2: o conceito que resolve

A lista de cartões (cada um com id, coluna, título, prioridade e data) é a verdade. Uma função apaga as colunas e desenha tudo de novo a partir da lista. Toda ação do usuário muda a lista e chama essa função.

Dica 3: onde estudar isso
  • Listas e objetos
  • Criar e apagar elementos

Marco 2: Criar, editar, excluir e salvar

Funciona quando: os casos 2 e 5 funcionam.

Travou? Abra uma dica de cada vez, e só depois de tentar de verdade.

Dica 1: uma pergunta para pensar

O localStorage só guarda texto. Como transformar uma lista de objetos em texto, e o texto de volta em lista? E como saber qual cartão editar se dois têm o mesmo título?

Dica 2: o conceito que resolve

JSON.stringify para salvar e JSON.parse para ler (dentro de try/catch, para o caso de estar vazio ou estragado). Dê a cada cartão um id único na criação, por exemplo crypto.randomUUID().

Dica 3: onde estudar isso
  • localStorage e JSON
  • try/catch

Marco 3: Mover, limitar e ordenar

Funciona quando: os casos 1 e 7 funcionam com o mouse e com o teclado.

Travou? Abra uma dica de cada vez, e só depois de tentar de verdade.

Dica 1: uma pergunta para pensar

Qual evento avisa "soltaram algo aqui"? E quem não usa mouse, como move um cartão?

Dica 2: o conceito que resolve

draggable="true" no cartão; dragstart guarda o id; dragover precisa de preventDefault() para permitir soltar; drop muda a coluna na lista. Para o teclado, botões ← e → no cartão. O limite de 3 é conferido antes de mudar a coluna. Para ordenar, sort com uma função que compara a prioridade e, se empatar, a data.

Dica 3: onde estudar isso
  • Eventos
  • Funções que comparam

Marco 4: Atrasados, filtros, exportar e importar

Funciona quando: os casos 3, 4 e 6 funcionam e o quadro está no ar.

Travou? Abra uma dica de cada vez, e só depois de tentar de verdade.

Dica 1: uma pergunta para pensar

Como comparar a data de entrega com hoje sem que o horário (e o fuso) atrapalhe?

Dica 2: o conceito que resolve

O campo type="date" dá o texto AAAA-MM-DD; monte o "hoje" no mesmo formato com a data local e compare os textos. Cuidado: toISOString() usa o horário de Londres. Exportar: um Blob e um link com download. Importar: input type="file" e FileReader; confira o conteúdo antes de trocar o quadro.

Dica 3: onde estudar isso
  • Dados e JSON
  • Tratar erros

5. Perguntas para pensar antes de programar

Responda no papel (ou no README). Elas apontam as armadilhas do projeto antes de você cair nelas. As respostas não estão aqui de propósito: é o que o projeto ensina.

  • Onde fica a "verdade" do quadro: no HTML da tela ou num array de objetos no JS? O que acontece se forem duas verdades diferentes?
  • Depois de mudar o array, como a tela fica igual a ele? Vale redesenhar tudo ou só o cartão que mudou?
  • O localStorage só guarda texto. Como guardar um array de objetos?
  • Como comparar a data de entrega com hoje sem errar por causa do horário?

Erro comum: ao recarregar, o quadro volta aos cartões de exemplo.

O código salva o exemplo por cima antes de ler o que estava guardado. Ordem certa: ler o localStorage; se não houver nada, usar o exemplo.

Erro comum: o cartão não solta na outra coluna.

Falta preventDefault() no evento dragover da coluna: sem ele, o navegador não permite soltar.

Erro comum: à noite, um cartão com entrega para hoje aparece atrasado.

É o fuso horário: toISOString() devolve a data de Londres, que já é amanhã. Monte a data de hoje com getFullYear, getMonth e getDate.

E a IA, neste passo?

Pode: pedir para explicar a ordem dos eventos de arrastar e soltar, ou por que o sort está ordenando errado, mostrando o seu código.

Não: pedir a função que desenha o quadro ou o arrastar e soltar prontos. Organizar o estado e redesenhar a tela é a habilidade que este projeto treina.
