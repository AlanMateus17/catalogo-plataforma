Linha do Tempo

2. Antes de começar

O que você vai praticar: HTML semântico, CSS responsivo com mobile first, variáveis CSS, imagens leves e publicação com a prévia certa no WhatsApp.

O que estudar antes (ou durante)

Tudo o que este projeto usa está explicado na Documentação:

  • Semântica: a tag certa para cada coisa
  • Textos, links e imagens
  • Modelo de caixa
  • Position
  • Responsivo e @media
  • Variáveis CSS
  • Passo 9: publicar no GitHub Pages

3. O que o sistema precisa fazer

Requisitos

  1. RF01 — Pelo menos 10 acontecimentos, cada um com data, título, texto curto e foto.
  2. RF02 — Um menu que leva a cada período (décadas ou fases) pela âncora.
  3. RF03 — No celular, a linha do tempo é uma coluna com a linha à esquerda; no computador, os acontecimentos alternam de lado.
  4. RF04 — Um acontecimento em destaque, visualmente diferente dos outros.
  5. RF05 — Rodapé com as fontes de cada informação e de cada foto.
  6. RF06 — Publicada no GitHub Pages, com o link e a imagem aparecendo certos ao compartilhar no WhatsApp.

Regras de negócio

  • RN01 — Só HTML e CSS. Nenhuma linha de JavaScript.
  • RN02 — HTML semântico: a linha do tempo é uma lista ordenada, cada acontecimento um artigo, cada data uma tag de data com o valor que as máquinas leem.
  • RN03 — Cada foto com texto alternativo, largura e altura, e no máximo 300 KB.
  • RN04 — Cores e espaços em variáveis CSS. Nenhuma cor repetida fora delas.

4. Construa em 4 marcos

Não tente fazer tudo de uma vez. Termine um marco, confira que funciona, faça um commit e só então passe para o próximo.

Marco 1: O conteúdo inteiro em HTML puro

Funciona quando: a página, ainda sem nenhum CSS, é lida de cima a baixo como um documento, com todos os acontecimentos na ordem.

Travou? Abra uma dica de cada vez, e só depois de tentar de verdade.

Dica 1: uma pergunta para pensar

Uma linha do tempo é uma sequência em que a ordem importa. Qual lista do HTML diz "a ordem importa"? E qual tag diz "isto é uma data" para o Google e para o leitor de tela?

Dica 2: o conceito que resolve

Uma lista ordenada <ol>, com um <article> em cada item e a data em <time datetime="1791-08-14">. Escreva tudo antes de qualquer CSS: se a página faz sentido assim, a estrutura está certa.

Dica 3: onde estudar isso
  • Semântica
  • Estrutura da página
  • Imagens e o atributo alt

Marco 2: A versão de celular

Funciona quando: em 360 px a linha do tempo é uma coluna, com a linha vertical à esquerda e um marcador em cada acontecimento.

Travou? Abra uma dica de cada vez, e só depois de tentar de verdade.

Dica 1: uma pergunta para pensar

A linha vertical é conteúdo ou decoração? Então ela deve existir no HTML ou ser desenhada pelo CSS?

Dica 2: o conceito que resolve

Decoração é CSS. A linha pode ser a borda esquerda da lista; o marcador de cada item, um ::before com position: absolute dentro de um item com position: relative.

Dica 3: onde estudar isso
  • Borda, padding e margin
  • Position relative e absolute
  • Variáveis CSS

Marco 3: A versão de computador

Funciona quando: a partir de uma largura que você escolheu, os acontecimentos alternam de lado, e o destaque continua diferente.

Travou? Abra uma dica de cada vez, e só depois de tentar de verdade.

Dica 1: uma pergunta para pensar

Você escreveu o CSS do celular primeiro. A partir de qual largura o layout deve mudar? E como escolher "um item sim, outro não" sem pôr uma classe em cada um?

Dica 2: o conceito que resolve

Mobile first: o @media (min-width: ...) só acrescenta o que muda no computador. :nth-child(even) escolhe os itens pares. Grid com duas colunas ou margens resolvem a alternância.

Dica 3: onde estudar isso
  • Responsivo e @media
  • Seletores, incluindo :nth-child
  • Grid

Marco 4: Fotos leves, prévia no WhatsApp e publicação

Funciona quando: cada foto pesa menos de 300 KB, a página está no GitHub Pages e o link mostra a prévia.

Travou? Abra uma dica de cada vez, e só depois de tentar de verdade.

Dica 1: uma pergunta para pensar

Quanto pesa cada foto? E em que tamanho ela aparece na tela? Faz sentido enviar uma foto de 4000 px para aparecer com 600?

Dica 2: o conceito que resolve

Redimensione cada foto para a largura em que ela aparece e salve em WebP ou JPG (qualidade perto de 80). Coloque width e height. Para a prévia, as metatags og:title, og:description e og:image, esta com o endereço completo (https://...).

Dica 3: onde estudar isso
  • Passo 9: publicar e caprichar no link compartilhado
  • Imagens

5. Perguntas para pensar antes de programar

Responda no papel (ou no README). Elas apontam as armadilhas do projeto antes de você cair nelas. As respostas não estão aqui de propósito: é o que o projeto ensina.

  • Se o CSS não carregar, a página ainda faz sentido? O que isso diz sobre o seu HTML?
  • A linha vertical é conteúdo ou decoração? Onde ela deve ser desenhada, no HTML ou no CSS?
  • Qual seletor escolhe "um item sim, outro não" sem colocar uma classe em cada um?

Erro comum: no celular aparece rolagem para o lado.

Algo está mais largo que a tela: uma imagem sem max-width: 100% ou uma largura fixa em px. No F12, passe o mouse pelos elementos até achar o que passa da borda.

Erro comum: a imagem não aparece na prévia do WhatsApp.

O og:image precisa do endereço completo, começando com https. O WhatsApp também guarda a prévia antiga: teste com o link seguido de ?v=2.

Erro comum: todos os acontecimentos ficam do mesmo lado.

O :nth-child precisa estar no elemento que se repete como filho da lista (o li), não no article de dentro, que é sempre o primeiro filho do seu li.

E a IA, neste passo?

Pode: pedir para revisar a semântica e a acessibilidade do seu HTML pronto, ou explicar por que um seletor não pegou o elemento que você queria.

Não: pedir o CSS da linha do tempo. Montar esse layout é o que o projeto ensina.

Por quê, e prompts prontos para usar do jeito certo: Usar IA do jeito certo.
