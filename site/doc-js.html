1. O que é JavaScript e onde ele roda

JavaScript é uma linguagem de programação: ao contrário do HTML e do CSS, ela guarda valores, faz contas, toma decisões, repete tarefas e reage ao que a pessoa faz. No navegador, ela lê e muda o HTML e o CSS da página enquanto a página está aberta.

O mesmo JavaScript também roda fora do navegador, no Node.js (servidores, ferramentas), e é a base do TypeScript e do Next.js, que você vai ver nos próximos módulos. Tudo o que você aprender aqui continua valendo lá.

O defer faz o script esperar o HTML inteiro ser lido. Sem ele, o JavaScript procura elementos que ainda não existem.

O Console: onde o JavaScript fala com você

Aperte F12 e abra a aba Console. Ali aparecem os erros (em vermelho, com o arquivo e a linha) e tudo o que você mandar mostrar com console.log. É a ferramenta número 1 para entender o que o código está fazendo.

Experimente: o seu primeiro programa

Clique em Rodar. Depois mude o texto e rode de novo.

Confira: Por que 2 + 3 deu 5 e "2" + "3" deu 23?

Ver a resposta

Com números, + soma. Com textos (entre aspas), + junta. "2" é um texto que parece número.

2. Sintaxe básica: como se escreve

  • O código é uma sequência de instruções, lidas de cima para baixo. Cada uma termina com ;.
  • Maiúsculas e minúsculas fazem diferença: querySelector funciona, queryselector dá erro.
  • Textos (strings) ficam entre aspas. Sem aspas, o JavaScript acha que é um nome.
  • Números sem aspas, com ponto no decimal: 1.75.
  • { } agrupam instruções (o corpo de um if, de uma função). ( ) chamam funções e guardam condições. [ ] fazem listas.
  • Comentários: // até o fim da linha, ou /* várias linhas */.
  • Nomes criados por você usam camelCase: botaoMenu, calcularImc. Sem acento, sem espaço, sem começar com número.

3. Variáveis e tipos de dados

Variável é uma caixa com nome que guarda um valor. Você cria com const (o nome não pode receber outro valor) ou let (o valor vai mudar). Regra prática: comece sempre com const; troque para let só se precisar dar outro valor depois.

Atenção: const impede trocar o valor inteiro (notas = [] dá erro), mas deixa mexer no que está dentro de uma lista ou objeto (notas.push(9) funciona).

string (texto)"Olá"nomes, mensagens, valores de campos

Erro comum: somar o valor de um campo

O que vem de um campo de formulário (.value) é SEMPRE texto. "2" + "3" dá "23". Converta antes: Number(campo.value).

6. Funções: dar nome a um bloco de código

Uma função é um bloco de código com nome, que só roda quando é chamado. Ela pode receber valores (parâmetros) e devolver um resultado (return). Use funções para não repetir código e para dar nome ao que o código faz.

Com e sem parênteses

calcularMedia(7, 9) com parênteses roda a função agora. calcularMedia sem parênteses é só o nome dela: é assim que se entrega uma função para o addEventListener rodar depois, no clique.

8. DOM: achar e mudar elementos da página

DOM é a árvore de elementos que o navegador montou a partir do HTML. O JavaScript mexe na página em três passos: achar o elemento, ler ou mudar alguma coisa, e (às vezes) criar elementos novos.

Divisão de tarefas

Prefira mudar a aparência trocando classes (classList) e deixar as cores e tamanhos no CSS. Assim, o JavaScript cuida do comportamento e o CSS da aparência, cada um no seu arquivo.

Erro comum: Cannot read properties of null

O querySelector não achou o elemento e devolveu null. Confira: o seletor está igual ao HTML (ponto para classe, # para id)? O script tem defer?

9. Eventos: reagir ao usuário

Evento é algo que acontece na página: um clique, uma tecla, um envio de formulário, a rolagem. Você liga uma função a um evento com addEventListener: "quando acontecer isto, rode aquilo".

EventoQuando acontece
"click"clique, toque, ou Enter/Espaço num botão
"input"a cada letra digitada
"change"terminou de mudar (select, checkbox)
"submit"envio do formulário (no form, não no botão)
"keydown"tecla apertada (evento.key diz qual)
"scroll"a página rolou

10. Guardar dados (localStorage) e controlar o tempo

O localStorage guarda no navegador de cada pessoa: não é um banco de dados. Se o aluno abrir o site em outro computador, os dados não estão lá. Para guardar de verdade, compartilhado entre pessoas, é preciso um servidor com banco de dados: é o assunto dos módulos 9 (API) e 10 (PostgreSQL).

11. Código assíncrono e fetch: a ponte para as APIs

Algumas tarefas demoram: buscar dados na internet, ler um arquivo. O JavaScript não trava a página esperando: ele recebe uma Promise (promessa de um valor que vai chegar). Com async/await, você escreve como se fosse em ordem, e a página continua respondendo.

Onde isso leva

fetch é como o front-end conversa com o back-end. No módulo 9 você vai criar, em C# com ASP.NET Core, a API que responde a esse fetch, e no módulo 10 guardar os dados no PostgreSQL.

12. Erros: ler, entender e consertar

Erro não é fracasso: é o computador dizendo exatamente o que não entendeu. Todo erro no Console tem tipo, mensagem e arquivo:linha. Leia os três antes de mexer no código.

MensagemO que quer dizerO que conferir
Uncaught SyntaxError: Unexpected tokenErro de escrita: sobrou ou faltou um sinalParênteses, chaves e aspas fechados? Vírgula a mais?
ReferenceError: x is not definedUsou um nome que não existeEscreveu igual (maiúsculas)? Criou com const/let?
TypeError: Cannot read properties of nullTentou usar um elemento que não foi achadoO seletor bate com o HTML? O script tem defer?
TypeError: x is not a functionChamou com () algo que não é funçãoNome do método certo? (addEventlistener ≠ addEventListener)
TypeError: Assignment to constant variableDeu outro valor a uma constTroque para let

Experimente: provoque e leia erros

Rode, leia o erro e a dica. Depois conserte o código.

  1. Leia o erro e clique no arquivo:linha: o navegador mostra a linha.
  2. Coloque console.log antes da linha com problema para ver os valores.
  3. Mude uma coisa de cada vez e teste.
  4. Ainda travado? Explique o problema em voz alta (ou para um colega). Muitas vezes a resposta aparece no meio da explicação.
