Preparar o computador

Antes de programar, o computador precisa de três programas e da sua conta no GitHub. No fim deste passo, o terminal já sabe quem você é.

1.1 Criar a conta no GitHub

O GitHub guarda o código do seu site e publica o site na internet. A conta é gratuita.

  1. Acesse github.com/signup.
  2. Digite o seu e-mail, crie uma senha e escolha o nome de usuário.
  3. O GitHub manda um código para o seu e-mail. Copie e cole na tela de cadastro.
  4. Se perguntar sobre planos, escolha o gratuito (Free).

O nome de usuário vai aparecer no endereço do seu site: https://seu-usuario.github.io/turismo-barbacena/. Escolha pensando nisso.

Erro comum: escolher um nome de usuário de brincadeira.

Daqui a dois anos, esse endereço pode estar no seu currículo. Prefira o seu nome, sem números aleatórios: anasouza ou ana-souza-dev.

Verificação em duas etapas: algumas semanas depois do cadastro, o GitHub pode exigir um segundo código no login. Quando ele pedir, instale um aplicativo autenticador no celular (Google Authenticator, Microsoft Authenticator) e guarde os códigos de recuperação num lugar seguro. Sem eles, quem perde o celular perde a conta.

1.2 Instalar o VS Code e o Live Server

  1. Baixe o VS Code em code.visualstudio.com e instale.
  2. Durante a instalação, marque as opções Adicionar ao PATH e Adicionar a ação "Abrir com Code". A primeira faz o comando code funcionar no terminal.
  3. Abra o VS Code, aperte Ctrl + Shift + X (Extensões), procure Live Server (autor: Ritwick Dey) e clique em Instalar.

O Live Server abre o seu site no navegador e recarrega a página sozinho toda vez que você salva um arquivo.

1.3 Instalar o Git (vem com o Git Bash)

O Git registra cada versão do seu projeto. Junto com ele vem o Git Bash, o terminal que vamos usar em toda a trilha.

  1. Baixe em git-scm.com, na parte de downloads para Windows, e abra o instalador.
  2. Pode aceitar as opções que já vêm marcadas. Se quiser, na tela Choosing the default editor used by Git, escolha Use Visual Studio Code as Git's default editor (o Passo 1.6 também resolve isso por comando).
  3. Termine a instalação.

1.4 Instalar o GitHub CLI

O GitHub CLI é o comando gh. Com ele você cria o repositório e publica o site sem sair do terminal. O Git sozinho não consegue fazer essas duas coisas.

  1. Baixe em cli.github.com o instalador para Windows e instale.
  2. Feche todos os terminais abertos. Os programas instalados só aparecem num terminal aberto depois da instalação.

Se o seu computador tiver o winget (Windows 10 e 11), dá para instalar os três programas de uma vez. Abra o PowerShell pelo menu Iniciar e digite (sem o $):

PowerShell
$ winget install -e --id Microsoft.VisualStudioCode$ winget install -e --id Git.Git$ winget install -e --id GitHub.cli

Pelo winget, o Git é instalado com as opções padrão. Os comandos do Passo 1.6 acertam o que ficaria faltando.

No laboratório da escola: se o computador não deixar instalar programas, peça ao professor. Faça os passos 1.5 a 1.7 depois que os programas estiverem instalados.

1.5 Conferir se deu certo

Abra o Git Bash pelo menu Iniciar e digite um comando de cada vez, apertando Enter depois de cada um:

Git Bash
$ git --version$ gh --version$ code --version

O que deve aparecer (no lugar de xx, os números da sua versão)

git version 2.xx.x.windows.1
gh version 2.xx.x (data da versão)
https://github.com/cli/cli/releases/tag/v2.xx.x
1.xx.x
(uma sequência longa de letras e números)
x64

Erro comum: bash: gh: command not found (ou git, ou code).

O terminal foi aberto antes da instalação, ou a instalação não terminou. Feche o Git Bash, abra de novo e repita. Se continuar, reinstale o programa e, no caso do VS Code, marque Adicionar ao PATH.

Confira: por que é preciso fechar e abrir o terminal depois de instalar um programa?

Ver a resposta

Porque o terminal lê a lista de programas disponíveis (o PATH) só quando abre. Um programa instalado depois não está nessa lista até você abrir um terminal novo.

1.6 Apresentar-se ao Git

Todo registro que você fizer (o commit) leva o seu nome e o seu e-mail. Use o mesmo e-mail da conta do GitHub: é assim que o GitHub liga os seus commits ao seu perfil.

Git Bash
$ git config --global user.name "Seu Nome Completo"$ git config --global user.email "seu-email@exemplo.com"$ git config --global init.defaultBranch main$ git config --global pull.rebase false$ git config --global core.editor "code --wait"$ git config --global --list

Troque o nome e o e-mail pelos seus antes de apertar Enter. No nome, as aspas são obrigatórias por causa dos espaços.

O que deve aparecer no último comando (pode ter outras linhas também)

user.name=Seu Nome Completo
user.email=seu-email@exemplo.com
init.defaultbranch=main
pull.rebase=false
core.editor=code --wait
ComandoPara que serve
user.name e user.emailQuem fez cada commit.
init.defaultBranch mainTodo repositório novo começa com o nome main, o mesmo que o GitHub usa.
pull.rebase falseDiz ao git pull como juntar as suas mudanças com as do GitHub. Sem isso, ele pode parar com Need to specify how to reconcile divergent branches.
core.editor "code --wait"Quando o Git precisar de um texto seu, ele abre o VS Code. Sem isso, pode abrir o Vim, um editor difícil de sair.

Erro comum: computador compartilhado (laboratório).

O --global vale para todo mundo que usar aquele usuário do Windows: os commits do colega sairiam com o seu nome. No laboratório, rode todos, menos os dois primeiros (os do nome e do e-mail). O nome e o e-mail você configura sem o --global, dentro da pasta do projeto, no Passo 4.3. Assim eles valem só para o seu projeto.

1.7 Entrar no GitHub pelo terminal

Este comando liga o terminal à sua conta. Depois dele, o git push e o gh funcionam sem pedir senha.

Git Bash
$ gh auth login

O comando faz algumas perguntas. Use as setas do teclado para escolher e Enter para confirmar:

PerguntaResponda
Where do you use GitHub? (ou: What account do you want to log into?)GitHub.com
What is your preferred protocol for Git operations?HTTPS
Authenticate Git with your GitHub credentials?Yes (aperte Y)
How would you like to authenticate GitHub CLI?Login with a web browser

O terminal mostra um código de 8 caracteres (ABCD-1234). Aperte Enter, o navegador abre, você entra na sua conta, digita o código e clica em Authorize. Volte ao terminal e confira:

Git Bash
$ gh auth status

O que deve aparecer (um trecho)

github.com
  ✓ Logged in to github.com account seu-usuario (keyring)
  - Active account: true
  - Git operations protocol: https

Erro comum: sair do laboratório sem sair da conta.

Quem sentar no computador depois consegue mexer nos seus repositórios. No fim de toda aula no laboratório, rode gh auth logout. Na próxima aula, faça o gh auth login de novo. Use sempre o gh para entrar: se algum dia o navegador pedir login num git push, o Windows guarda essa senha em Gerenciador de Credenciais > Credenciais do Windows, e ela precisa ser removida lá (item git:https://github.com).

Você tenta

Rode gh auth status e encontre, na resposta, o seu nome de usuário. Depois abra https://github.com/ + o seu usuário no navegador: é o seu perfil público.

Pronto quando

Marque cada item só depois de conferir. As marcações ficam salvas neste navegador e aparecem na página inicial da trilha.
