10.1 O ciclo de todo dia

  1. Traga o que mudou em outro lugar: git pull.
  2. Edite e salve no VS Code.
  3. Confira no Live Server.
  4. Registre e envie.
Git Bash: antes de editar
$ git pull

Depois de editar, salvar e conferir no Live Server:

Git Bash: depois de editar
$ git status$ git add .$ git commit -m "Adiciona galeria de fotos"$ git push

Espere um ou dois minutos e recarregue o site no ar com Ctrl + F5.

Uma boa mensagem de commit diz o que mudou, começando por um verbo: Adiciona formulário de contato, Corrige link do menu, Troca cores do tema. Evite ajustes ou aaa: daqui a um mês, nem você vai saber o que fez.

Erro comum: nothing to commit, working tree clean.

O Git não viu nenhuma mudança. Você salvou o arquivo (Ctrl + S)? Está na pasta certa?

Erro comum: o git push respondeu Everything up-to-date e o site não mudou.

Faltou o git commit. O push só envia o que já virou commit.

Erro comum: ! [rejected] main -> main (fetch first) ou Updates were rejected no push.

O GitHub tem mudanças que o seu computador não tem (você mexeu em outro computador ou pelo site). Rode git pull e depois git push de novo. Se o VS Code abrir um arquivo de mensagem, feche a aba: o Git continua sozinho.

Erro comum: CONFLICT (content): Merge conflict in index.html no pull.

Você mudou a mesma linha em dois computadores. Abra o arquivo no VS Code: ele mostra as duas versões com os botões Accept Current e Accept Incoming. Escolha, salve e rode git add ., git commit -m "Resolve conflito" e git push.

10.2 Ver o que mudou e voltar a uma versão

Git Bash
$ git diff$ git log --oneline
  • git diff mostra o que você mudou desde o último commit: linhas com - saíram, com + entraram.
  • git log --oneline lista os commits, do mais novo para o mais antigo, cada um com um código (3f2a9c1).
  • git restore index.html desfaz as mudanças do index.html que ainda não viraram commit. Cuidado: o que você tinha mudado se perde.

Estragou um arquivo e já fez commit? Traga de volta a versão dele de um commit antigo, usando o código que aparece no git log --oneline:

Git Bash
$ git restore --source=3f2a9c1 css/estilo.css$ git add .$ git commit -m "Volta o estilo.css para a versão anterior"$ git push

Troque 3f2a9c1 pelo código do commit em que o arquivo estava bom, e o nome do arquivo pelo seu.

Erro comum: o terminal "travou" com um : ou (END) no final.

O git log e o git diff abrem uma tela de leitura. Use as setas para rolar e aperte q para sair.

Confira: você mudou uma cor, fez git commit e o site no ar não mudou. Cite dois motivos possíveis.

Ver a resposta

Faltou o git push, ou o GitHub Pages ainda está publicando (espere e use Ctrl + F5). Também pode ser cache do navegador.

10.3 Continuar em outro computador

No laboratório, em casa ou num computador novo, entre na sua conta e baixe o projeto do GitHub com clone:

Git Bash
$ gh auth status# se não estiver logado: gh auth login (Passo 1.7)$ mkdir -p ~/projetos$ cd ~/projetos$ gh repo clone seu-usuario/turismo-barbacena$ cd turismo-barbacena$ code .

No laboratório, depois do clone, rode os dois git config sem --global do Passo 4.3. Já tem o projeto nesse computador? Então comece toda sessão com git pull (10.1).

Erro comum: To get started with GitHub CLI, please run: gh auth login.

O terminal não está logado (normal no laboratório, depois do logout da aula anterior). Rode gh auth login (Passo 1.7).

Erro comum: fatal: not a git repository.

Você está fora da pasta do projeto. Rode cd ~/projetos/turismo-barbacena e repita.

Erro comum: sair do laboratório logado.

No fim da aula, rode gh auth logout. Na próxima, faça o gh auth login de novo (Passo 1.7).

Você tenta

Faça três mudanças pequenas no seu site, cada uma com o seu commit e o seu push. Depois abra o repositório com gh repo view --web e clique em commits: as três mensagens estão lá.

Pronto quando

Marque cada item só depois de conferir. As marcações ficam salvas neste navegador e aparecem na página inicial da trilha.
